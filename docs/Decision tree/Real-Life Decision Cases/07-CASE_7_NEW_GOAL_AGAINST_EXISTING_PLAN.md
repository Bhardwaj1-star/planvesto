# Case 7 — New Goal Against an Existing Financial Plan

## 1. Real-Life Financial Case

An investor already has an established financial plan.

That plan is based on:

- the current Financial State;
- existing goals;
- existing feasibility calculations;
- selected strategies;
- implementation decisions;
- and an active Action Plan.

The investor then introduces a **new goal**.

For example:

> The investor already has an Education Goal and Retirement Goal, and now wants to add a Dream Home Goal.

The investor has limited financial resources.

Therefore, adding the new goal can directly affect:

- existing goal funding;
- available monthly surplus;
- existing assets;
- liquidity;
- debt;
- other financial-state measurements;
- and the feasibility of existing goals.

The important point is:

> **The new goal should not automatically be inserted into the existing financial plan.**

It should first be evaluated separately so the investor can understand its consequences.

---

## 2. Question — What Should Happen When a New Goal Is Introduced?

The existing financial plan should remain intact initially.

The new goal should be treated as a **separate planning scenario** against the existing plan.

The system should calculate:

1. the new goal's funding requirement;
2. the new goal's individual feasibility;
3. the additional resources required;
4. the impact on existing goals;
5. the impact on the Financial State;
6. alternative funding paths;
7. the consequences of implementing those alternatives.

The investor should then be able to decide whether they want to accept the resulting trade-offs.

---

## 3. Why the Investor's Role Is Important

Financial resources are limited.

Adding a new goal can change the financial requirements of the complete plan.

The system should therefore not automatically decide:

> "The new goal is more important, so reduce the retirement allocation."

Instead, the system should show the investor:

> **"If you add this goal, this is what happens to your existing financial plan."**

The investor can then decide:

- whether the new goal is worth the trade-off;
- whether to change the goal amount;
- whether to change the timeline;
- whether to use existing assets;
- whether to increase available surplus;
- whether to use a different funding mechanism;
- whether to implement a particular strategy;
- or whether not to add the goal at all.

This makes the investor an active participant in the financial decision.

---

## 4. New Goal Should Initially Be a Separate Scenario

The existing plan should not be modified merely because a new goal has been proposed.

The conceptual flow is:

**Existing Financial Plan**

+

**Proposed New Goal**

↓

**Separate New-Goal Analysis**

↓

**Funding Requirement**

↓

**New-Goal Feasibility**

↓

**Impact on Existing Goals**

↓

**Impact on Financial State**

↓

**Alternative Paths**

↓

**Investor Decision**

Only when the investor accepts the proposed change should the new goal become part of the actual financial plan.

---

## 5. Example

Suppose the existing plan contains:

- Education Goal — ₹50 lakh in 8 years
- Retirement Goal — ₹3 crore in 22 years

The existing plan is already feasible and has an active strategy and Action Plan.

The investor now proposes:

- Dream Home — ₹1 crore in 7 years.

The system should not immediately change the Education or Retirement strategy.

Instead, it should create a separate scenario:

### "What happens if I add this Dream Home goal?"

The system can then show:

- required monthly contribution;
- required lump sum;
- available resources;
- funding gap;
- effect on Education;
- effect on Retirement;
- effect on liquidity;
- effect on debt;
- alternative funding paths;
- and the resulting changes if the investor chooses to implement one of them.

The investor can then participate in the scenario using their own financial numbers.

---

## 6. Investor Can Play With the New Goal

The new-goal scenario should allow the investor to test alternatives.

For example:

### Option A

Dream Home:

- ₹1 crore;
- 7-year timeline;
- current available surplus.

### Option B

Change the target:

- ₹80 lakh;
- same timeline.

### Option C

Change the timeline:

- ₹1 crore;
- 10-year timeline.

### Option D

Use existing assets:

- deploy a specified portion of current assets;
- reduce the required monthly contribution.

### Option E

Change the funding mechanism:

- use an appropriate financing/funding mechanism;
- preserve selected existing assets where appropriate.

The system should recalculate the consequences of each scenario.

This is not automatically a change to the investor's actual plan.

It is a **participatory decision environment**.

---

## 7. The Two Implementation Layers

Case 7 establishes an important distinction between two types of implementation.

### Implementation Layer 1 — Goal / Strategy Implementation

This concerns the implementation of a particular strategy for a particular goal.

The investor asks:

> **"What happens if I implement this strategy for this goal?"**

Example:

**Education Goal**

↓

**Credit Utilisation Strategy**

↓

Investor tests the actual financial numbers and implementation.

The output shows the consequences of implementing that strategy for the goal.

---

### Implementation Layer 2 — Whole-Plan Impact Simulation

This concerns the impact of introducing a new goal or another major financial situation into the existing financial plan.

The investor asks:

> **"What happens to my entire financial plan if I add this new goal?"**

The system evaluates:

**Existing Financial Plan**

+

**New Goal / New Financial Situation**

↓

**Whole-Plan Impact**

This can show:

- existing goal feasibility changes;
- required contribution changes;
- asset allocation changes;
- liquidity changes;
- debt changes;
- impact on existing strategies;
- impact on Action Plan;
- and alternative paths.

These two implementation layers should not be treated as the same function.

---

## 8. Investor Decision Comes Before Plan Adoption

The new-goal scenario should not automatically modify the existing financial plan.

The investor first sees the consequences.

The investor then decides whether to:

- accept the new goal;
- modify the new goal;
- change its timeline;
- change its funding;
- choose an alternative path;
- or reject the new goal.

If the investor accepts the change, the system can then incorporate the new goal into the actual financial plan and recalculate the required planning outputs.

Therefore:

> **Simulation first. Adoption second.**

---

## 9. Relationship to Multi-Goal Planning

Case 3 and Case 7 are related but different.

### Case 3 — Existing Multiple Goals

Multiple goals are already part of the planning problem.

The system must construct an overall feasible path across those goals.

### Case 7 — New Goal Against an Existing Plan

An existing financial plan already exists.

The investor proposes an additional goal.

The system first evaluates:

> **"What is the incremental impact of adding this goal to my existing plan?"**

The investor decides whether to accept the trade-off.

Only after acceptance does the new goal become part of the actual multi-goal planning problem.

---

## 10. Relationship to Strategy Builder

Strategy Builder should not automatically decide whether the investor should sacrifice an existing goal to accommodate the new goal.

Its role remains to determine the appropriate strategy for the accepted financial path.

The broader sequence is:

**Existing Financial Plan**

+

**Proposed New Goal**

↓

**New-Goal Scenario / Whole-Plan Impact Simulation**

↓

**Investor Decision**

↓

If Accepted:

**Updated Multi-Goal Feasibility**

↓

**Strategy Builder**

↓

**Implementation**

↓

**Action Plan**

The Strategy Builder therefore operates on the financial path that the investor has chosen to pursue.

---

## 11. Action Plan

Action Plan remains the actual implementation layer.

If the investor accepts the new goal, the resulting Action Plan may include:

- additional monthly contribution;
- deployment of existing assets;
- changes to existing allocations;
- debt-related actions;
- strategy-specific execution actions;
- changes to existing goal contributions;
- and sequencing/timing of the required actions.

If the investor does not accept the new goal, the existing Action Plan remains unchanged.

---

## 12. Established Business Decisions

From this case, the following principles are established:

1. An existing financial plan should remain intact when a new goal is merely proposed.
2. A proposed new goal should initially be evaluated as a separate scenario against the existing plan.
3. The system should calculate the new goal's funding requirement and individual feasibility.
4. The system should show the incremental impact of the new goal on the existing financial plan.
5. The system should identify alternative paths for accommodating the new goal.
6. The investor, not the system, decides whether to accept the trade-offs.
7. The investor should be able to participate using their actual financial numbers.
8. Implementation should support experimentation with the new goal before adoption.
9. There are two distinct implementation perspectives:
   - goal/strategy implementation;
   - whole-financial-plan impact simulation.
10. A new goal should become part of the actual financial plan only after the investor accepts the proposed change.
11. Once accepted, the new goal can enter the normal multi-goal feasibility and strategy process.
12. Strategy Builder should determine the strategy for the accepted path; it should not unilaterally sacrifice existing goals to accommodate a proposed new goal.
13. Action Plan translates the accepted financial path into the investor's actual actions.
14. The exact scenario-comparison, adoption, and approval mechanics remain subject to implementation validation.

---

## 13. Decision Boundary

The established relationship is:

**Existing Financial Plan**

↓

**Proposed New Goal**

↓

**Separate Scenario**

↓

**Whole-Plan Impact Simulation**

↓

**Investor Decision**

### If rejected

**Existing Financial Plan continues unchanged.**

### If accepted

**Updated Multi-Goal Planning**

↓

**Feasibility**

↓

**Strategy Builder**

↓

**Goal/Strategy Implementation**

+

**Whole-Plan Impact Validation**

↓

**Action Plan**

↓

**Investor Execution**

This preserves the existing plan while giving the investor a controlled way to evaluate and adopt new financial goals.

---

## 14. Final Business Principle

> **A proposed new goal should first be treated as a scenario against the investor's existing financial plan. The system shows the financial consequences and trade-offs; the investor decides whether to accept them.**

And:

> **Implementation has two perspectives: implementing a strategy for a particular goal, and simulating the effect of a new goal or financial situation on the entire financial plan.**
