# User Journey System Map

**Document Type:** User Journey Map  
**Status:** CANONICAL DESIGN  
**Feature journey naming:** Use canonical feature names (e.g., Strategy Builder), not internal stage names (e.g., Strategy Decision).

## Core Journey

```
Onboarding → Financial State → Goal Planning → Goal Feasibility
→ Strategy Builder → Implementation Design → What-If / Stress
→ Decision & Recommendation → Investor Adoption → Accepted Plan
→ Action Plan → Execution
```

## Change Journey

```
Accepted Plan → Change Trigger → Impact Analysis → Targeted Revalidation
→ Updated Decision → Investor Adoption → Updated Accepted Plan
```

## Plan-Level Branch

New goals or material changes may trigger Whole-Plan / Multi-Goal Impact before adoption.

## Core Rule

A User Journey describes **what the investor does, what the system does, what the investor sees, and where the investor decides**. Detailed decision logic remains in Decision Tree and architecture documents.
