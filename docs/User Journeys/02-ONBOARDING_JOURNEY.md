# Onboarding Journey

**Document Type:** User Journey  
**Status:** CANONICAL DESIGN

## Journey

```
Investor starts → Provides planning information → Goals / priorities
→ System validates → Initial Financial State → Investor reviews
→ Continue to Planning
```

## Investor Does
1. Provides required personal and financial planning information.
2. States goals and priorities.
3. Reviews and corrects captured information.
4. Continues when the starting information is acceptable.

## System Does
- Validates and normalises inputs.
- Builds the initial Financial State.
- Identifies missing information.
- Does not invent unavailable financial facts.

## Handoff

```
Validated Investor Context + Financial State → Goal Planning
```

## Core Rule

Onboarding captures the investor's starting state. It does not decide the investment Strategy.
