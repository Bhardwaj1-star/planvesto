# Action Plan Journey

**Document Type:** User Journey  
**Status:** CANONICAL DESIGN

## Journey

```
Accepted Plan → Implementation Requirements → Action Plan
→ Investor Reviews Actions → Prioritise / Confirm → Execution
```

## Each Action Should Make Clear
- What to do
- Amount
- Timing
- Source
- Destination
- Order
- Dependency
- Status
- Expected impact
- Revalidation trigger, where relevant

## Investor Does
- Reviews required actions.
- Confirms practical execution.
- Changes timing when appropriate.
- Tracks completion.

## Core Rule

Action Plan is the bridge between an Accepted Plan and real-world execution. It is not a generic task list.
