# No Acceptable Path Journey

**Document Type:** User Journey  
**Status:** CANONICAL DESIGN

## Journey

```
Goal / Plan → Candidate Strategies Evaluated
→ Constraints / Viability / Resilience → No Acceptable Path
→ Investor Sees Why → Investor Chooses:
   ├─ Change Goal
   ├─ Change Assumptions
   ├─ Reconsider Constraints
   ├─ Wait / Defer
   └─ Design an Alternative
```

## Investor Experience

The system shows:
- what prevents the current path;
- which alternatives were considered;
- what would need to change.

## Core Rule

**No acceptable Strategy is a valid outcome.** The system must not force a recommendation merely because the user expects one.
